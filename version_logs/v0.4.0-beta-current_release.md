# Version 0.4.0 (beta)

A modernization release: current Python and dependencies, production-ready credentials, type hints, a test suite and automated releases. Existing code keeps working in most cases; read **Breaking changes** before upgrading.

## Breaking changes:
- **Python 3.11 or newer** is required (was 3.6).
- **Dependencies are optional extras.** `pip install instackup` installs only pandas and PyYAML. Install what you use: `instackup[gcp]`, `instackup[aws]`, `instackup[gsheets]`, `instackup[postgresql]`, `instackup[mysql]`, `instackup[redshift]`, or everything with `instackup[all]`.
- **No more log files.** The library no longer creates a `logs/` folder; it logs through the standard `logging` module and no longer prints. Configure logging in your application.
- Google tools no longer set the `GOOGLE_APPLICATION_CREDENTIALS` environment variable.
- `S3Tool.delete_subfolder`, `S3Tool.rename_subfolder`, `GCloudStorageTool.delete_subfolder` and `GCloudStorageTool.rename_subfolder` raise `ValueError` when no subfolder is set, instead of acting on the whole bucket.
- `S3Tool.rename_subfolder`, `delete_subfolder` and `download_subfolder` now include nested "folders".
- `GCloudStorageTool.get_bucket_info` returns `datetime` objects for `TimeCreated` and `TimeUpdated`.
- `GCloudStorageTool.list_contents` skips "folder" placeholder objects.
- `GSheetsTool.upload` with `write_mode="APPEND"` adds rows after the existing data instead of reading and rewriting the whole sheet; with `force_upload=True` and different columns, rows are added by position.
- `BigQueryTool.convert_postgresql_table_schema`: JSON columns become `NULLABLE` RECORDs (were `REPEATED`, which BigQuery rejects for single objects).
- `RedShiftTool` no longer has `access_key`/`secret_key` attributes.
- `code_location()` returns `None` instead of raising `KeyError` when no location is configured.

## New functionalities:
- **New credentials system** ([docs/credentials.md](../docs/credentials.md)), in the new `credentials` module:
  - `INSTACKUP_<SERVICE>__<CONNECTION>__<KEY>` environment variables;
  - AWS Secrets Manager (`INSTACKUP_AWS_SECRET_ID`) and GCP Secret Manager (`INSTACKUP_GCP_SECRET_NAME`);
  - `${VAR}` / `${VAR:-default}` references in credential files, so they can be committed without secrets;
  - Google Application Default Credentials and the AWS default credential chain when no credentials are configured (Workload Identity, IAM roles...);
  - `CredentialStore`, `get_credentials()`, `get_default_store()`, `set_default_store()`.
- Every tool accepts explicit `credentials=`; cloud tools also accept a ready SDK object (`client=`, `session=`, `gspread_client=`).
- Database connection settings accept a `url` (e.g. `postgresql://user:pass@host/db`).
- `query` and `execute_sql` accept `params=` for parameterized queries.
- `RedShiftTool`: `iam_role` setting/argument used by `unload_to_S3` instead of embedding AWS keys; `session` property.
- `GSheetsTool`: `auth_mode="default"` (Application Default Credentials).
- `S3Tool.download_file` has a `replace` parameter.
- `GCloudStorageTool.upload_from_dataframe` sets the file's content type (`text/csv` or `application/json`).
- `upload_file` (S3 and GCS) keeps the local file name when the remote path ends with "/".
- Tool classes can be imported from the package root, e.g. `from instackup import BigQueryTool`.
- Type hints everywhere (`py.typed`).

## Bug fixes:
- general_tools
  - `parse_remote_uri` rejects URIs without a bucket.
- sql_tools
  - `SQLiteTool.describe_table` returned the wrong query result; it now returns the table's columns.
  - `MySQLTool` failed with the documented `dbname` setting.
  - `PostgreSQLTool.describe_table` was open to SQL injection through the table name.
  - Backticks were removed from MySQL and SQLite queries, breaking quoted identifiers.
  - `get_all_db_info` failed on JSON columns holding arrays or scalars.
  - Using a tool after a silently failed connection raised `AttributeError`.
- redshift_tools
  - `RedShiftTool(connect_by_cluster=False)` raised `NameError`.
  - Temporary cluster credentials were requested at creation and could expire before `connect()`.
- s3_tools
  - `rename_file`, `delete_file`, `upload_subfolder` and `download_file` (without a folder) always failed.
- gcloudstorage_tools
  - URIs ending in "/" or with only a bucket were parsed incorrectly.
  - `get_file_info` returned empty metadata.
  - `upload_subfolder` and `download_subfolder` always failed.
  - `rename_subfolder` produced wrong names when the new subfolder had no trailing "/".
  - `download_file` built wrong paths when `download_to` was a folder without a trailing "/".
- bigquery_tools
  - `convert_postgresql_table_schema` marked every column `REQUIRED`, and dropped every regular column with `parse_json_columns=False`.
  - `list_tables_in_dataset(return_type="list")` returned the last table repeated.
  - `upload` failed with pandas 3 (`DataFrame.to_gbq` was removed).
  - `start_transfer` failed with current library versions and with transfers outside the US location.
  - `convert_dataframe_to_numeric` ignored text columns with pandas 3.
  - `get_table_schema` returned nested fields as objects instead of dictionaries.
  - Invalid `writing_mode` or `file_format` raised `KeyError` (now `ValueError`, even when creating the table).
  - A second Google connection silently reused the first one's service account.
- gsheets_tools
  - Uploads with missing values, dates or Decimal values failed.
  - URLs with `&range=` after the `#gid=` failed.
  - `set_spreadsheet_by_key` kept the worksheet of the previous spreadsheet.
- heroku_tools
  - Commands were run through a shell and could be injected through arguments.
- Downloading a subfolder (S3 and GCS) skips object names containing `..` that would be written outside the target folder.

## Deprecated:
- `general_tools.fetch_credentials`: use `credentials.get_credentials()` or `credentials.get_default_store().get_value()`.

## Removed dependencies:
- `gcsfs`, `oauth2client` (via Composer auth) and the `grpcio` pin.

## Development:
- `pyproject.toml` (hatchling) replaces `setup.py`; the version comes from git tags.
- Test suite with pytest (unit tests with fakes and moto, integration tests against PostgreSQL and MySQL).
- GitHub Actions: CI on Python 3.11–3.15, Linux, macOS and Windows; publishing to PyPI on GitHub releases with Trusted Publishing ([docs/releasing.md](../docs/releasing.md)).
